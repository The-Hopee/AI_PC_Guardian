# CLOUD-001 — Развёртывание в Timeweb Cloud

## Статус

Запланирована. Выполняется после `DEPLOY-001` и `SEC-001`: небезопасный gRPC-порт
нельзя сначала открыть в интернет с обещанием защитить его позже.

## Цель

Развернуть защищённый контейнер `guardian-server` на одном Ubuntu VPS в Timeweb
Cloud и подтвердить RPC с Windows-компьютера через публичный домен.

## Инфраструктура первого стенда

- один небольшой Ubuntu LTS VPS;
- публичный IPv4;
- домен вида `api.<домен>:443`;
- Docker Engine и Docker Compose plugin;
- облачный Firewall Timeweb;
- TLS endpoint и приватная Docker network;
- без Kubernetes, балансировщика и нескольких серверов.

## Сеть

1. Привязать публичный IPv4 к VPS.
2. Создать DNS `A`-запись домена на этот IPv4.
3. Разрешить входящий TCP `443` для клиентов.
4. Разрешить SSH `22` только с доверенного административного IP, если это
   практически возможно.
5. Не открывать наружу `50051`, базы данных и Docker daemon.
6. Запретить весь ненужный входящий трафик.

`.env` не открывает порт и не создаёт маршрутизацию: за доступность отвечают
публичный IP, DNS, Firewall, Docker port mapping и адрес прослушивания процесса.

## Развёртывание

- создать отдельного непривилегированного пользователя для приложения;
- передать `compose.yaml` и получить/собрать закреплённый image;
- создать серверный `.env` вне Git;
- запустить `docker compose up -d`;
- проверить статус, логи и автоматический restart;
- сохранить инструкцию обновления image и отката на предыдущую версию;
- настроить минимальный мониторинг свободного диска, памяти и доступности процесса.

## Ручная приёмка

С Windows-компьютера вне сети VPS:

```powershell
guardian-agent.exe --server api.example.com:443
```

Ожидается:

- TLS-проверка проходит;
- авторизованное устройство получает подтверждение `event_id`;
- сервер логирует принятый ID без токена и полного payload;
- неверный токен отклоняется;
- закрытый порт `50051` недоступен напрямую по публичному IP.

## Эксплуатационная документация

Описать:

- первоначальное создание VPS;
- Firewall и DNS;
- расположение compose/config/secrets на сервере;
- запуск, остановку, обновление и просмотр логов;
- ротацию токена и сертификата;
- проверку занятого порта;
- откат после неуспешного обновления.

## Критерии готовности

- клиент выполняет защищённый RPC по доменному имени;
- после перезапуска VPS контейнер поднимается автоматически;
- секреты отсутствуют в репозитории;
- наружу открыт только необходимый минимум портов;
- задокументирован воспроизводимый deploy и rollback;
- расходы на VPS и публичный IPv4 зафиксированы перед созданием ресурсов.

## Не входит в задачу

- production SLA;
- несколько регионов;
- автоматическое масштабирование;
- Kubernetes;
- managed database;
- CI/CD;
- публичный релиз клиента.
