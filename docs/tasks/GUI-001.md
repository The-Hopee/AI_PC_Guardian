# GUI-001 — Первый экран Qt 6/QML с CPU/RAM

## Статус

Проверена на Windows с Qt 6.8.3 и MSVC 2022. Target `guardian-desktop` собран,
QML прошёл `qmllint`, окно проверено вручную, а значения CPU/RAM обновляются
автоматически без блокировки интерфейса. Все 12 тестов проекта проходят.

## Цель

Создать первый видимый вертикальный срез AI PC Guardian: отдельное Windows-окно,
которое показывает настоящую текущую загрузку CPU и физической памяти, состояние
обновления и простую локальную оценку высокой нагрузки.

```text
WinAPI collectors → фоновая C++ задача → ViewModel → QML dashboard
```

Сервер для этого экрана не требуется. Это осознанный прототип интерфейса; связь с
постоянно работающим Agent будет добавлена через локальный IPC отдельным этапом.

## Технологии

- Qt 6.5 или новее;
- Qt Quick и Qt Quick Controls 2;
- QML для компоновки и визуального слоя;
- `QObject`, `Q_PROPERTY`, signals для передачи состояния из C++;
- Qt Concurrent для сбора CPU без блокировки UI-потока;
- существующий target `Guardian::WindowsCollectors`.

QML-файлы подключаются современным CMake API `qt_add_qml_module`, а не старым
`.qrc` вручную или qmake-проектом.

## Структура

```text
desktop/
├── CMakeLists.txt
├── include/guardian/desktop/system_metrics_view_model.hpp
├── src/main.cpp
├── src/system_metrics_view_model.cpp

    └── MetricCard.qml
```

## ViewModel

`SystemMetricsViewModel` публикует в QML:

- `cpuUsage` — общая загрузка CPU в процентах;
- `memoryUsage` — доля занятой RAM;
- `memoryUsedGiB` и `memoryTotalGiB`;
- `statusText` — текущее состояние или ошибка collectors;
- `lastUpdated` — время последнего завершённого снимка;
- `refreshing` — защита от параллельных повторных запусков;
- `refresh()` — ручной или периодический запрос нового снимка.

Сбор CPU занимает около 400 мс и поэтому выполняется не в GUI-потоке. Пока одна
задача работает, следующий вызов `refresh()` игнорируется.

## Экран

Первый экран содержит:

- заголовок и индикатор состояния;
- отдельные карточки CPU и RAM;
- анимированные полосы загрузки;
- цветовое предупреждение при CPU от 85% или RAM от 90%;
- краткий диагностический блок;
- кнопку ручного обновления;
- автоматическое обновление раз в три секунды.

Пороговая оценка в `GUI-001` только визуальная. Настоящая диагностическая модель
findings и правила причин появятся в `DIAG-001`.

## CMake

Корневая опция:

```text
GUARDIAN_BUILD_DESKTOP=ON
```

включена по умолчанию. Если Qt не найден, CMake сообщает об этом и продолжает
сборку Agent/Server/тестов. После установки Qt создаётся target:

```text
guardian-desktop
```

Пример конфигурации:

```powershell
cmake -S . -B build `
  -G "Visual Studio 17 2022" -A x64 `
  -DCMAKE_PREFIX_PATH="C:/Qt/<version>/msvc2022_64"
cmake --build build --config Debug --target guardian-desktop
```

## Обработка ошибок

- ошибка CPU не уничтожает последнее успешное значение RAM;
- ошибка RAM не уничтожает последнее успешное значение CPU;
- пользователю показывается понятный статус;
- повторный refresh не создаёт параллельные `GetSystemTimes`;
- закрытие окна дожидается завершения текущего короткого сбора.

## Критерии готовности

- QML не содержит захардкоженных значений CPU/RAM;
- интерфейс остаётся отзывчивым во время CPU sample;
- значения обновляются автоматически и по кнопке;
- существующая сборка работает без установленного Qt;
- после установки Qt target собирается и окно проверяется вручную;
- Qt deployment и установщик оформляются отдельным этапом.

## Не входит в задачу

- связь GUI с фоновым Agent через IPC;
- графики истории;
- отправка на сервер;
- AI-чат и рекомендации;
- настройка адреса сервера;
- системный трей;
- установщик и `windeployqt`;
- визуальные тесты на нескольких DPI и темах.
