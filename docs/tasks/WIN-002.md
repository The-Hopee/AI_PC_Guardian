# WIN-002 — Сборщик метрик CPU/RAM

## Статус

Реализована и проверена на Windows/MSVC. Агент получает настоящие показатели
CPU/RAM через WinAPI и отправляет серверу два отдельных события.

Автоматическая проверка: 11 из 11 CTest-тестов пройдены. При ручной приёмке агент
показал реальные значения CPU и физической памяти, а сервер подтвердил оба ID.

## Цель

Получить один корректный снимок общей загрузки CPU и физической памяти средствами
WinAPI, преобразовать значения в существующие `CpuMetric`/`MemoryMetric` и
однократно отправить два отдельных события работающему `guardian-server`.

```text
GetSystemTimes ─────────→ CpuMetric
                             ↓
GlobalMemoryStatusEx ───→ MemoryMetric
                             ↓
                    TelemetryClient
                             ↓
                     guardian-server
```

Периодический фоновый сбор, Windows Service и метрики отдельных процессов в эту
задачу не входят.

## Почему CPU требует два измерения

`GetSystemTimes()` возвращает накопительные счётчики времени с момента запуска
Windows, а не готовый процент. Нужно получить два снимка с интервалом и вычислить
разницу:

```text
total_delta = kernel_delta + user_delta
busy_delta  = total_delta - idle_delta
usage       = busy_delta / total_delta * 100
```

В Windows `kernel time` уже включает `idle time`, поэтому складывать только
`user + kernel - idle` нужно именно в такой последовательности.

## Публичный API

Предлагаемая структура:

```text
agent/include/guardian/agent/windows/system_metrics_collector.hpp
agent/src/windows/system_metrics_collector.cpp
tests/agent/system_metrics_collector_test.cpp
```

Предлагаемый интерфейс:

```cpp
namespace guardian::agent::windows {

struct CpuTimes {
    std::uint64_t idle;
    std::uint64_t kernel;
    std::uint64_t user;
};

[[nodiscard]]
std::optional<guardian::model::CpuMetric> calculate_cpu_metric(
    const CpuTimes& previous,
    const CpuTimes& current) noexcept;

[[nodiscard]]
std::optional<guardian::model::CpuMetric> collect_cpu_metric(
    std::chrono::milliseconds sample_interval);

[[nodiscard]]
std::optional<guardian::model::MemoryMetric> collect_memory_metric() noexcept;

}  // namespace guardian::agent::windows
```

`CpuTimes` и чистая функция расчёта нужны, чтобы математику можно было полноценно
проверить без подмены WinAPI и ожидания реального интервала в каждом unit-тесте.

## Сбор CPU

`collect_cpu_metric()` должен:

1. Отклонить неположительный `sample_interval`.
2. Вызвать `GetSystemTimes()` и преобразовать три `FILETIME` в `std::uint64_t`.
3. Подождать заданный интервал; рекомендуемое CLI-значение — 500 мс.
4. Получить второй снимок `GetSystemTimes()`.
5. Передать снимки в `calculate_cpu_metric()`.
6. Вернуть `std::nullopt` при ошибке WinAPI или некорректных счётчиках.

`calculate_cpu_metric()` должен проверить:

- счётчики не уменьшились;
- `total_delta > 0`;
- `idle_delta <= total_delta`;
- результат конечный и находится в `[0.0, 100.0]`.

## Сбор памяти

`collect_memory_metric()` должен:

1. Создать `MEMORYSTATUSEX` и заполнить `dwLength`.
2. Вызвать `GlobalMemoryStatusEx()`.
3. Записать `ullTotalPhys` в `total_bytes`.
4. Записать `ullAvailPhys` в `available_bytes`.
5. Проверить `total_bytes > 0` и `available_bytes <= total_bytes`.
6. Вернуть `std::nullopt` при ошибке.

Нельзя использовать общий объём виртуальной памяти вместо физической RAM.

## CMake

- создать библиотеку `guardian_windows_collectors`;
- добавить alias `Guardian::WindowsCollectors`;
- собирать target только на Windows;
- связать его с `Guardian::Common`;
- `guardian-agent` связать с `Guardian::WindowsCollectors`;
- WinAPI-функции не должны появляться в `common` или `proto`.

## Интеграция в агент

Обычный запуск агента должен:

1. Собрать CPU и RAM.
2. Создать два `TelemetryEvent` с разными event ID и общим device ID.
3. Отправить CPU-событие через существующий `TelemetryClient`.
4. Отправить memory-событие.
5. Напечатать собранные значения и оба подтверждённых ID.
6. Завершиться с ненулевым кодом, если сбор или одна из отправок не удались.

На этом этапе device ID может оставаться временным идентификатором процесса.
Постоянная идентификация устройства оформляется отдельной задачей.

## Тесты

Обязательные автоматические проверки:

1. Из известных счётчиков вычисляется ожидаемый CPU percentage.
2. Нулевая разница времени отклоняется.
3. Уменьшившиеся счётчики отклоняются.
4. `idle_delta > total_delta` отклоняется.
5. Результат всегда находится в `[0, 100]`.
6. Реальный `collect_cpu_metric()` на Windows возвращает валидную метрику.
7. Реальный `collect_memory_metric()` возвращает `total_bytes > 0` и
   `available_bytes <= total_bytes`.
8. Существующие 10 тестов остаются зелёными.

Реальные smoke-тесты не должны проверять конкретный процент CPU или объём RAM:
эти значения зависят от компьютера и текущей нагрузки.

## Ручная приёмка

1. Запустить `guardian-server`.
2. Запустить `guardian-agent`.
3. Убедиться, что агент показывает реальные CPU/RAM и два event ID.
4. Убедиться, что сервер принял оба ID.
5. Сравнить порядок величины памяти с Windows Task Manager.

## Последовательность реализации

1. Реализовать преобразование `FILETIME` и чистый расчёт CPU.
2. Написать unit-тесты математики.
3. Реализовать `collect_cpu_metric()`.
4. Реализовать `collect_memory_metric()`.
5. Добавить CMake-target collectors.
6. Добавить Windows smoke-тесты.
7. Заменить синтетическое событие в `guardian-agent` двумя реальными.
8. Запустить полный CTest и ручную приёмку.
9. Обновить README и статус задачи.

## Критерии готовности

- CPU и RAM получены через WinAPI, а не захардкожены;
- значения проходят существующий `guardian::model::is_valid()`;
- математика CPU тестируется отдельно от WinAPI;
- ошибки системных вызовов не превращаются в ложные нулевые метрики;
- агент отправляет и сервер подтверждает два разных события;
- все тесты проходят на Windows/MSVC;
- платформенный код не попадает в `common`.

## Не входит в задачу

- загрузка отдельных ядер CPU;
- список и метрики процессов;
- GPU, VRAM и температуры;
- диск и сеть;
- WMI, PDH и ETW;
- периодический сбор;
- локальное хранение;
- Windows Service;
- постоянный device ID.
