# AI-001 — OpenRouter и выбор доверенной модели

## Статус

Запланирована. Интеграция выполняется на сервере после появления структурированного
диагностического контекста. Windows Agent не должен напрямую обращаться к
OpenRouter или хранить его API-ключ.

## Принятое решение по моделям

Пользовательский выбор ограничен тремя доверенными семействами:

| Логическое имя Guardian | OpenRouter model ID по состоянию на 24.08.2026 |
| --- | --- |
| `claude-sonnet` | `~anthropic/claude-sonnet-latest` |
| `claude-opus` | `~anthropic/claude-opus-latest` |
| `gpt-5.6-sol` | `openai/gpt-5.6-sol` |

Другие модели не показываются и не принимаются от клиента. Конкретные provider ID
хранятся в серверной конфигурации и обязательно повторно проверяются через Models
API OpenRouter перед реализацией и каждым изменением allowlist.

Алиас `latest` удобен для доверия всему семейству, но может незаметно менять
поведение и стоимость. Для воспроизводимого production-релиза допускается заменить
его закреплённым ID конкретной версии без изменения клиентского логического имени.

## Цель

Добавить серверный интерфейс AI-провайдера и реализацию OpenRouter, которая
получает безопасный диагностический контекст, обращается только к разрешённой
модели и возвращает объяснение пользователю.

```text
Windows UI: logical model choice
    ↓
Guardian Server: allowlist + diagnostic context
    ↓ HTTPS
OpenRouter: configured provider model ID
    ↓
Guardian Server: validated answer + usage
    ↓
Windows UI
```

## Границы ответственности AI

- детектирование базовых проблем выполняют правила/анализатор, а не LLM;
- LLM объясняет findings, связывает контекст и формирует рекомендации;
- модель не получает право самостоятельно выполнять команды на компьютере;
- ответ считается рекомендацией, а не доказанным диагнозом;
- рискованные действия требуют отдельной проверки и явного подтверждения
  пользователя.

## Серверный интерфейс

Предусмотреть независимую от OpenRouter абстракцию:

```cpp
enum class AiModel {
    claude_sonnet,
    claude_opus,
    gpt_5_6_sol,
};

struct AiRequest {
    AiModel model;
    std::string diagnostic_context;
    std::string user_question;
};

struct AiResponse {
    bool success{false};
    std::string answer;
    std::string error_message;
    std::uint64_t input_tokens{0};
    std::uint64_t output_tokens{0};
};

class AiProvider {
public:
    virtual ~AiProvider() = default;
    virtual AiResponse complete(const AiRequest& request) = 0;
};
```

Точный HTTP-клиент для C++ выбирается при реализации отдельным коротким
исследованием. Он должен поддерживать HTTPS, deadline, ограничение размера ответа
и подменяемый transport для тестов.

## Конфигурация и секреты

```env
OPENROUTER_API_KEY=
GUARDIAN_MODEL_CLAUDE_SONNET=~anthropic/claude-sonnet-latest
GUARDIAN_MODEL_CLAUDE_OPUS=~anthropic/claude-opus-latest
GUARDIAN_MODEL_GPT_5_6_SOL=openai/gpt-5.6-sol
GUARDIAN_DEFAULT_MODEL=claude-sonnet
GUARDIAN_AI_MAX_OUTPUT_TOKENS=
```

- реальный ключ присутствует только на сервере;
- ключ не попадает в Git, клиент, protobuf, логи и сообщения об ошибках;
- клиент отправляет enum/логическое имя, а не произвольный OpenRouter slug;
- неизвестная модель отклоняется до платного HTTP-запроса;
- Claude Opus помечается в UI как более дорогой вариант;
- сервер задаёт максимальное число выходных токенов и deadline;
- автоматический retry платного запроса по умолчанию отключён, чтобы исключить
  неожиданные повторные списания.

## Приватность

- в модель отправляется минимальный нормализованный диагностический контекст;
- сырые дампы, токены, имена файлов и персональные данные не отправляются без
  отдельной необходимости и согласия;
- перед первым AI-запросом интерфейс объясняет, какие данные уйдут третьей стороне;
- содержимое prompt/answer не логируется по умолчанию;
- usage и технический request ID разрешено логировать без пользовательских данных.

## Контроль расходов

- вести учёт input/output tokens из ответа;
- задавать лимит выходных токенов;
- ограничивать число запросов на устройство/пользователя;
- перед публичным запуском задать месячный budget alert в аккаунте провайдера;
- не позволять клиенту выбирать batch/pro/fast-варианты обходом allowlist;
- показывать пользователю, какой логический класс модели выбран.

## Тесты

Автоматические тесты не должны тратить деньги или обращаться к OpenRouter.

1. Каждое логическое имя отображается в правильный настроенный provider ID.
2. Неизвестная модель отклоняется до HTTP-вызова.
3. API-ключ добавляется только в серверный Authorization header.
4. Успешный фиктивный JSON-ответ преобразуется в `AiResponse`.
5. HTTP 401, 402, 429, 5xx и timeout дают безопасные ошибки.
6. Слишком большой или некорректный ответ отклоняется.
7. Учёт токенов извлекается корректно.
8. Секрет не появляется в логах или error message.

Разрешается отдельный ручной smoke test с настоящим ключом и минимальным prompt.
Он запускается только явно и не регистрируется как обычный CTest.

## Критерии готовности

- сервер выполняет настоящий запрос к каждой из трёх разрешённых моделей;
- произвольную четвёртую модель выбрать невозможно;
- Windows-клиент не содержит OpenRouter API key;
- AI-ошибка не ломает приём телеметрии и обычную диагностику;
- расходы и token usage наблюдаемы;
- приватность и отправляемые поля задокументированы;
- unit/integration tests используют поддельный локальный HTTP transport.

## Не входит в задачу

- OpenCode Server как production backend Guardian;
- локальные LLM;
- автоматический выбор любых моделей из каталога;
- обучение и fine-tuning;
- автономное выполнение исправлений;
- биллинг конечных пользователей и подписки;
- хранение полного AI-чата.
