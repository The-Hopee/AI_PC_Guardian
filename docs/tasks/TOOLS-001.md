# TOOLS-001 — Диагностическое логирование

## Статус

Реализована на Windows/MSVC. Контрольная проверка на Linux/GCC остаётся частью
общей кроссплатформенной приёмки проекта.

## Цель

Заменить разрозненный вывод прикладного кода через стандартные потоки единым
потокобезопасным журналом. После штатной остановки или аварии разработчик должен
видеть последовательность последних операций Agent и Server.

## Архитектура

Логгер расположен в отдельной статической библиотеке `Guardian::Tools` и
предоставляется как singleton `guardian::tools::Logger`. Singleton создаётся
стандартной локальной статической переменной C++ и существует один раз в каждом
процессе.

Поддерживаются уровни:

- `DEBUG` — подробности выполнения и ожидания;
- `INFO` — штатные изменения состояния;
- `WARN` — восстановимые отклонения;
- `ERROR` — неудачная операция;
- `CRITICAL` — невозможность продолжить работу.

Каждая запись содержит дату и время с миллисекундами, уровень, идентификатор
потока, логический компонент, сообщение, исходный файл и строку вызова.

## Файлы журналов

На Windows журналы создаются в `%LOCALAPPDATA%/AI_PC_Guardian/logs`:

- `guardian-agent.log`;
- `guardian-server.log`.

На Linux используется `$XDG_STATE_HOME/ai-pc-guardian/logs`, а при отсутствии
переменной — `$HOME/.local/state/ai-pc-guardian/logs`.

Файл открывается в режиме добавления. После каждой записи выполняется `flush`,
чтобы минимизировать потерю последних сообщений при аварии.

## Обработка ошибок

- Ошибка создания каталога или открытия файла не завершает приложение: вывод
  остаётся доступен в консоли.
- Ошибки самого логирования подавляются, чтобы диагностическая подсистема не
  ломала бизнес-логику.
- Terminate-handler фиксирует причину необработанного C++-исключения, вызывает
  `flush` и завершает процесс.
- Логгер не заменяет crash dump: access violation и точный нативный stack trace
  потребуют отдельной Windows-интеграции с WER/DbgHelp или minidump.

## Тесты

- создание вложенного каталога и файла;
- запись всех уровней;
- наличие компонента и `файл:строка`;
- конкурентная запись из нескольких потоков без смешивания строк.

## Критерии готовности

- прикладной Agent и Server не используют прямые `std::cout`, `std::cerr` или
  `std::clog`;
- журнал пишется одновременно в консоль и файл;
- Agent и Server используют разные файлы;
- тест логгера и полный CTest-набор проходят;
- README сообщает пользователю расположение журналов.

## Не входит в задачу

- ротация и ограничение общего размера журналов;
- удалённая отправка журналов;
- автоматическое сокрытие произвольных секретов;
- Windows minidump и символизация stack trace;
- пользовательский экран просмотра логов.
