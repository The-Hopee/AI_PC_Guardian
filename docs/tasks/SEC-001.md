# SEC-001 — Защищённое удалённое gRPC-соединение

## Статус

Запланирована. Выполняется после `DEPLOY-001` и обязательно до открытия сервера
для публичного интернета.

## Цель

Заменить публичное небезопасное gRPC-соединение на TLS-канал с аутентификацией
устройства. Ни телеметрия, ни токен не должны передаваться открытым текстом.

## Целевая схема

```text
Windows Agent
    ↓ gRPC over HTTP/2 + TLS, Bearer device token
TLS endpoint :443
    ↓ закрытая Docker network
guardian-server:50051
```

TLS может завершаться в reverse proxy с поддержкой gRPC/HTTP2. Внутренний порт
`guardian-server` не публикуется в интернет.

## Аутентификация устройства

- каждому устройству выдаётся отдельный случайный токен;
- клиент отправляет `authorization: Bearer <token>` в gRPC metadata;
- сервер проверяет токен до обработки `SubmitTelemetry`;
- неверный или отсутствующий токен возвращает `UNAUTHENTICATED`;
- токен не записывается в логи и protobuf-сообщения;
- компрометация одного токена не должна требовать замены токенов остальных
  устройств;
- для первого MVP разрешена ручная выдача и отзыв токенов через серверную
  конфигурацию; полноценный аккаунт пользователя относится к отдельному этапу.

## TLS

- внешний endpoint использует доменное имя и доверенный сертификат;
- Windows Agent проверяет сертификат и имя сервера;
- `InsecureChannelCredentials()` запрещены для публичной конфигурации;
- сертификат и закрытый ключ не хранятся в Git или Docker image;
- должен быть описан способ обновления сертификата без пересборки приложения;
- наружу публикуется TCP `443`, внутренний `50051` доступен только контейнерам.

## Конфигурация

Предусмотреть раздельные параметры:

```text
GUARDIAN_PUBLIC_HOST
GUARDIAN_DEVICE_TOKEN
GUARDIAN_TLS_CA_FILE
```

Серверные секреты передаются через окружение или mounted secret-файлы. Репозиторий
содержит только `.env.example` с пустыми значениями.

## Тесты

1. Клиент с тестовым CA и правильным токеном выполняет RPC.
2. Соединение без доверенного сертификата отклоняется.
3. Неверное имя сервера приводит к ошибке TLS.
4. Отсутствующий токен возвращает `UNAUTHENTICATED`.
5. Неверный токен возвращает `UNAUTHENTICATED`.
6. Правильный токен не меняет существующую валидацию телеметрии.
7. Тесты работают локально и не обращаются к интернету.

## Критерии готовности

- перехват сетевого трафика не раскрывает protobuf-содержимое или токен;
- публичное соединение невозможно без проверки сертификата;
- сервер отклоняет неизвестные устройства до обработки payload;
- секреты отсутствуют в Git, логах и Docker image history;
- описана ручная ротация сертификата и токена.

## Не входит в задачу

- OAuth и социальный вход;
- личный кабинет;
- платные подписки;
- mutual TLS;
- автоматическая регистрация устройств;
- полноценный rate limiting и защита от DDoS.
