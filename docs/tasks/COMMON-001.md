# COMMON-001 — Модель данных Guardian

## Статус

Реализована и проверена локальным набором Windows-тестов.

## Цель

Создать небольшую платформонезависимую C++17-модель первых событий телеметрии
Guardian. В дальнейшем она должна преобразовываться в Protobuf, но не зависеть
от сгенерированного кода или API операционной системы.

## Границы задачи

Первая версия модели поддерживает:

- общую загрузку CPU;
- общий и доступный объём физической памяти;
- идентификаторы события и устройства;
- время с точностью до миллисекунд;
- необязательный идентификатор процесса.

Новые типы payload добавляются только вместе со сборщиком или функцией, которой
они действительно нужны.

## Публичная модель

Пространство имён: `guardian::model`.

### Идентификаторы

```cpp
struct EventId { std::string value; };
struct DeviceId { std::string value; };
struct ProcessId { std::uint32_t value; };
```

`Timestamp` — `std::chrono::system_clock::time_point` с точностью до
миллисекунд.

### Метрики

```cpp
struct CpuMetric {
    double usage_percent;
};

struct MemoryMetric {
    std::uint64_t total_bytes;
    std::uint64_t available_bytes;
    std::uint64_t used_bytes() const noexcept;
};
```

`used_bytes()` возвращает `total_bytes - available_bytes`. Если доступная память
больше общего объёма, функция возвращает ноль и не допускает unsigned underflow.
Такая метрика всё равно считается невалидной.

### Оболочка события

```cpp
enum class EventType { CpuMetric, MemoryMetric };
using EventPayload = std::variant<CpuMetric, MemoryMetric>;

struct TelemetryEvent {
    EventId id;
    Timestamp timestamp;
    DeviceId device_id;
    std::optional<ProcessId> process_id;
    EventPayload payload;
};
```

Отдельное поле типа события намеренно не хранится. `event_type()` определяет тип
по активной альтернативе `std::variant`, поэтому тип и payload не могут
противоречить друг другу.

## Правила валидации

`is_valid()` возвращает `false`, если:

- идентификатор события пустой;
- идентификатор устройства пустой;
- значение CPU не является конечным числом, меньше `0.0` или больше `100.0`;
- общий объём памяти равен нулю;
- доступная память больше общего объёма.

Диапазон timestamp и семантика process ID в этой задаче не проверяются.

## Разделение файлов

- `identifiers.hpp` — идентификаторы и alias времени;
- `metrics.hpp` — структуры метрик CPU и памяти;
- `telemetry_event.hpp` — variant payload, оболочка и публичные операции;
- `telemetry_event.cpp` — visitors, валидация и вычисляемые значения;
- `telemetry_event_test.cpp` — тесты модели.

Все публичные заголовки открывают общий namespace `guardian::model`.
Вспомогательные visitors находятся в анонимном namespace внутри `.cpp`.

## Тестовые сценарии

- занятая память вычисляется корректно;
- полностью доступная память даёт ноль занятых байт;
- некорректные значения памяти не вызывают underflow;
- оба payload правильно преобразуются в `EventType`;
- границы CPU `0.0` и `100.0` принимаются;
- отрицательный, превышающий 100, NaN и бесконечный CPU отклоняются;
- корректные значения памяти принимаются;
- нулевой общий объём и превышающий его доступный объём отклоняются;
- пустые event ID и device ID отклоняются.

## Критерии готовности

- `Guardian::Common` является статической библиотекой с публичными заголовками;
- публичные заголовки не зависят от Windows или Linux API;
- реализация собирается с настроенным уровнем предупреждений;
- модель имеет отдельную цель CTest;
- все базовые тесты и тесты модели проходят;
- README содержит минимальный пример модели.

## Не входит в задачу

- генерация UUID и device ID;
- Protobuf, JSON и сериализация в базу данных;
- реальный сбор CPU/RAM;
- payload для GPU, процессов, сети, игр и ошибок;
- подробные сообщения об ошибках валидации;
- хранение и передача событий.
