# DEPLOY-001 — Docker-образ сервера

## Статус

Запланирована. Выполняется после появления локального сквозного пути
`guardian-agent → guardian-server`; рекомендуемая точка старта — после `WIN-002`.

## Цель

Создать воспроизводимый Linux-контейнер `guardian-server`, который одинаково
собирается и запускается локально и на VPS. Контейнеризация не должна менять
gRPC-контракт или переносить Windows Agent в Docker.

## Результат

```text
исходный код
    ↓ docker build
builder image: CMake + компилятор + FetchContent
    ↓ копирование артефактов
runtime image: guardian-server + runtime-зависимости
    ↓ docker compose up
локальный gRPC-сервер
```

## Требования к Dockerfile

- использовать multi-stage build;
- зафиксировать базовые образы по версии, не применять плавающий `latest`;
- собирать `Release` с `BUILD_TESTING=OFF`;
- в runtime-образ копировать только нужный executable и runtime-зависимости;
- запускать процесс не от `root`;
- запускать сервер с `--address 0.0.0.0:50051` внутри контейнера;
- корректно доставлять `SIGTERM` непосредственно процессу сервера;
- не помещать API-ключи, сертификаты и `.env` внутрь образа;
- добавить `.dockerignore` для build-каталогов, Git и локальных секретов.

## Docker Compose

Добавить `compose.yaml` и `.env.example`.

До появления TLS небезопасный gRPC-порт разрешено публиковать только на loopback
хоста:

```yaml
ports:
  - "127.0.0.1:50051:50051"
```

Публичная публикация `0.0.0.0:50051:50051` не входит в этот этап.

Compose должен:

- передавать адрес запуска аргументом или переменной конфигурации;
- использовать `restart: unless-stopped`;
- не содержать реальные секреты;
- позволять увидеть логи через `docker compose logs`;
- корректно завершать сервер через `docker compose stop`.

## Проверки

1. Образ собирается с чистым Docker build cache.
2. В runtime-образе отсутствуют компилятор и исходный код.
3. Контейнер запускается обычным непривилегированным пользователем.
4. Windows-клиент на том же компьютере выполняет настоящий RPC через опубликованный
   loopback-порт.
5. `docker compose stop` приводит к сообщению `Stopping server` и штатному выходу.
6. После остановки порт освобождается.
7. Секреты и build-артефакты не попадают в Git или image history.

## Критерии готовности

- `docker build` и `docker compose up` описаны в README;
- сервер доступен локально из Windows Agent;
- образ имеет закреплённую и документированную основу;
- контейнер не требует ручной установки gRPC/Protobuf на хост;
- полный CTest нативной Windows-сборки остаётся зелёным.

## Не входит в задачу

- аренда VPS;
- публичный IP и DNS;
- TLS и аутентификация;
- база данных;
- CI/CD и registry;
- Docker-контейнер для Windows Agent;
- Kubernetes.
